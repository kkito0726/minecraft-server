# 管理コンソール（mcadmind）

バックアップの取得と復元、複数ワールドの切り替え、サーバーの起動・停止を
ブラウザから行うための常駐プロセス。手順書どおりに `save-off` を打って
`save-on` を忘れる、という事故をなくすために作った。

要件と設計の詳細は [spec/admin-console/](spec/admin-console/) にある。
画面の操作が何を呼んで `data/` と `.env` に届くかは
[sequence/](sequence/) に図で書いた。1 ユースケースにつき 1 ファイルに分けてある。
ここは**動かす側の手順**だけを扱う。
日々の起動・停止と障害対応は [runbook.md](runbook.md) にまとめてある。

---

## できること / できないこと

| できる | できない（v1 では作らない） |
|---|---|
| バックアップの取得（稼働したまま / 停止して）・一覧・削除・世代管理 | コンソール（RCON）を画面から叩く |
| 外から持ち込んだ zip の取り込みと、手元の PC への持ち出し | プレイヤー管理（op / whitelist / ban / kick） |
| バージョンを検証したうえでの復元 | TPS の表示、資源の推移グラフ（履歴は持たない） |
| ワールドの一覧・新規作成・複製・改名・削除・切り替え | `.env` の自由な編集（バージョン・種別・メモリ・ワールド名は画面から変えない） |
| サーバーの起動・停止・再起動と状態表示 | 複数利用者・権限分け |
| ゲーム設定（難易度・ゲームモード・MOTD・最大人数・距離）の保存と反映 | バックアップの自動転送・スケジュール実行 |
| ホストの CPU・メモリ・ストレージの使用状況（現在値） | プレイヤーごとの統計 |
| 進行中の操作の手順とログの表示 | — |

**操作の取り消しはできない。** 復元の途中で止めると「退避済み・展開途中」という
最も悪い状態になるため、中断の口を用意していない。

## 置き方

### 1. バイナリを用意する

タグ（`v*`）を打つと GitHub Actions が Release を作り、`linux/arm64` と
`linux/amd64` のバイナリを添える。Pi の上で落とすのが既定の経路で、
**Pi 側に Go も Node も要らない。**

```bash
cd ~/minecraft-server
./deploy/download.sh      # uname を見て資産を選び、SHA256SUMS で検証して置く
```

版を固定したいときは `--tag v1.0.0`。切り戻しも同じ形でできる。

`download.sh` は `uname -s` / `uname -m` から `mcadmind-<os>-<arch>` を選ぶ。
配っているのは Linux の arm64 と amd64 だけで、macOS 向けは無い
（開発機で動かすだけなら次の `make build` がある）。32bit の Raspberry Pi OS は
arm64 のバイナリを掴ませず、理由を出して止まる。

URL を直に叩くなら、検証まで含めてこうなる（`<arch>` は `arm64` か `amd64`）。

```bash
curl -fsSLO https://github.com/kkito0726/minecraft-server/releases/latest/download/mcadmind-linux-<arch>
curl -fsSLO https://github.com/kkito0726/minecraft-server/releases/latest/download/SHA256SUMS
sha256sum --ignore-missing -c SHA256SUMS
```

`curl` で落ちてくるファイルは 644 だが、`install.sh` が `install -m 0755` する
ので直さなくてよい。

同じ機械でビルドして同じ機械で動かすなら `make build` でよい。

タグを打つ前の変更を実機で試したい場合や、Pi が GitHub へ出られない場合は、
手元でクロスビルドして `scp` で送る手順が
[build-from-source.md](build-from-source.md) にある。

### 2. トークンを決める

```bash
openssl rand -hex 32
```

出力を `.env` の `ADMIN_TOKEN` に書く。**32 文字未満だと起動時に止まる。**
`.env.example` は空で配っているので、初回は必ずここで止まる。

### 3. systemd に登録する

```bash
sudo deploy/install.sh --project-dir ~/minecraft-server
```

何を置くか先に見たいときは `--dry-run` を付ける。何も書き換えず、置こうとする
ユニットの中身だけを表示する。

```bash
deploy/install.sh --dry-run
```

置いたあとの確認。

```bash
systemctl status mcadmind
journalctl -u mcadmind -f
```

### 4. ブラウザで開く

```
http://<Tailscale のホスト名 or 100.x.y.z>:8787
```

初回だけトークンを聞かれる。以降はブラウザに保存される。

### 5. ポート番号なしで開く（任意・推奨）

`tailscale serve` を挟むと、ポート番号なしの HTTPS で開けるようになる。

```bash
sudo tailscale serve --bg 8787     # Pi の上で実行する
tailscale serve status             # 設定の確認
```

これで次の URL になる。証明書は Tailscale が取得・更新する。

```
https://<ホスト名>.<tailnet 名>.ts.net
```

**先に tailnet の管理画面で MagicDNS と HTTPS 証明書を有効にしておくこと。**
どちらかが無効だと証明書を取れず、`serve` は失敗する。

得られるものは 3 つある。

- ポート番号が消える。URL を口頭で伝えやすくなる。
- **経路が暗号化される。** 直接 8787 を開く場合は平文で、共有トークンもそのまま流れる。
- 80 番や 443 番を掴むのは tailscaled なので、**mcadmind に root も特権も要らない。**

あわせて `.env` の `ADMIN_ADDR` を `127.0.0.1:8787` に絞れる。外向きの受け口は
tailscaled が持つため、mcadmind はループバックだけで待てばよくなり、
家庭内 LAN からの到達面も閉じられる。

代償は、Tailscale が落ちている間は管理画面も開けなくなること。もともと tailnet 経由を
前提にしているので実質は変わらないが、`ADMIN_ADDR` を絞った場合は Pi にログインして
`tailscale serve reset` するまで戻せない点は意識しておく。

設定はノードに保存され、再起動後も残る。やめるときは次のとおり。

```bash
sudo tailscale serve reset
```

> `tailscale funnel` とは別物。`serve` は tailnet の中だけに公開する。
> `funnel` はインターネットへ公開するもので、この管理画面には向かない
> （[security-review.md](security-review.md) を参照）。

## 到達できる範囲

**RCON の 25575 は変わらず公開しない。** 管理コンソールも `docker compose exec -T mc rcon-cli`
を経由するので、RCON がネットワークに出ることはない。

到達の制御は 2 段にしている。

| 段 | 何を守るか |
|---|---|
| Tailscale | tailnet の外からは届かない |
| `ADMIN_TOKEN` | tailnet の中の他の端末・他の人からも守る |

`ADMIN_ADDR` の既定を `0.0.0.0:8787` にしてあるのは、`127.0.0.1` だと Pi の外から
開けず、しかも原因が分かりにくいため。

ただし **`0.0.0.0` は「同一ネットワークだけ」という意味ではない。** その機械が持つ
全ての差込口で受けるので、tailnet だけでなく**家庭内 LAN からも届く**。
インターネット側から届かないのは、ルーターが 8787 を転送していないからであって、
`0.0.0.0` のおかげではない。LAN 側を守っているのは `ADMIN_TOKEN` だけになる。

閉じたい場合は `tailscale serve` を使い、`ADMIN_ADDR` を `127.0.0.1:8787` に絞る
（上の「ポート番号なしで開く」）。経路も暗号化される。

トークンはブラウザの localStorage に置く。XSS に晒される代わりに使い勝手を取った
判断で、Go 側で `default-src 'self'` の CSP と `nosniff` を付けて緩和している。
単一利用者・tailnet 内という前提での割り切りであることは意識しておく。

## 画面

### `/` サーバーの状態

コンテナの状態、ヘルスチェック、稼働時間、接続人数、ワールドのバージョン。
起動・停止・再起動もここから行う。人が接続している状態で停止・再起動を押すと、
一度確認を挟む。

**「保存が止まっているかもしれない」赤い帯**が出ることがある。前回の操作が
途中で終わった（プロセスが kill された、Pi が落ちた）ときの印。RCON には
「保存が有効か」を問い合わせる手段がないため、状態は推定でしかない。
起動時と、コンテナが healthy になるたびに `save-on` を無条件で送り直している。

### `/worlds` ワールド

一覧、新規作成、複製、改名、削除、切り替え。

**新規作成では、ゲームモード・難易度・ハードコアも決める。** この 3 つが効くのは
生成の瞬間だけで、後から変えてもゲームモードは新しく接続した人にしか効かず、
ハードコアは `level.dat` に焼かれた値と食い違う。だから作成の画面で受け取る。

ただし **いずれもサーバー全体の設定であって、ワールドごとの属性ではない。**
指定した値は `.env`（`MC_MODE` / `MC_DIFFICULTY` / `MC_HARDCORE`）に書かれる。
クリエイティブで作ったワールドから別のワールドへ切り替えても、モードは
クリエイティブのまま残る。戻したければ `/settings` で選び直す。
例外はハードコアで、これは切り替えのたびにワールドの `level.dat` に合わせる（下記）。

**ハードコアはモードの選択肢のひとつとして並べている。** 別のチェック欄にすると
「クリエイティブ + ハードコア」のような意味の無い組み合わせを選べてしまう。
遊ぶ側から見てもハードコアはサバイバルの一種なので、排他の選択にまとめた。
送る値は `MC_MODE=survival` と `MC_HARDCORE=TRUE` になる。

ハードコアを選ぶと**難易度は選べなくなる**。Minecraft がハードに固定するためで、
選ばせると画面と実際の挙動が食い違う。`.env` にも `MC_DIFFICULTY=hard` を書く
（指定があっても上書きする）。

選んだ時点で警告を出し、ワールド名の完全一致を打たせる。死亡が不可逆になり、
生成後は外せないため（削除と同じ扱いにしてある）。ハードコアを選ばずに作った
ときは `MC_HARDCORE=FALSE` を明示的に書く。前に作ったハードコアのワールドの
設定を、次のワールドが黙って引き継がないため。

**切り替えると、ハードコアの設定はワールドに付いていく。** `MC_HARDCORE` は
サーバー全体の値だが、ハードコアかどうかは本来ワールドが `level.dat` に持って
いる（26.x では `Data.difficulty_settings.hardcore`）。切り替えのたびにそこを読んで
`.env` を合わせる。

| 切り替え | `MC_HARDCORE` | `MC_DIFFICULTY` |
|---|---|---|
| → ハードコアのワールド | `TRUE` にする | `hard` にする（ハードコアでは固定のため） |
| ハードコア → 普通のワールド | `FALSE` にする | そのワールドの `level.dat` の難易度に戻す |
| 普通 → 普通 | `FALSE` のまま | 触らない（`/settings` で決める値） |
| `level.dat` が読めない | **触らない** | 触らない |

読めないときに `FALSE` を書かないのは、読めなかっただけのハードコアのワールドを
普通にしてしまわないため。ハードコアのワールドには一覧で印が付くので、
切り替える前に分かる。何を合わせたかは操作のログにも残る。

ゲームモード（`MC_MODE`）は合わせない。取り違えても死亡が不可逆になるような
取り返しのつかない結果にはならず、`/settings` でいつでも選び直せる。切り替えの
たびに変わると、かえって驚かせる。ハードコアだけを特別扱いするのはこのため。

**切り替えはサーバーの再作成を伴う。** `LEVEL` は起動時に一度しか読まれないため、
`docker compose restart` では反映されない。切り替え前のワールドは 1 バイトも動かず、
`data/<名前>/` にそのまま残る。いつでも戻せる。

削除は既定で退避（`data/<名前>.deleted-<日時>` へ `mv`）。完全に消すには
「退避したワールド」から改めて削除する。

### `/backups` バックアップ

取得、一覧、削除、保持ポリシー、そして復元。

取得の方式は 2 つ。

| 方式 | 中身 | いつ使うか |
|---|---|---|
| 稼働したまま（既定） | `save-off` → `save-all` → zip → `save-on` | 普段はこちら |
| 停止してから | `down` → zip → `up -d` | 確実に取りたいとき |

メモを添えられるが、**ファイル名に残るのは英数字と下線だけ**なので、日本語のメモは
消える。打っている最中に、実際に残る形を画面が見せる。

**手元の PC に保存できる。** 一覧の「ダウンロード」から、そのアーカイブを zip のまま落とせる。
取得した直後でも後日でも、一覧にある限り何度でも押せる。

リンクは押すたびに発行され、10 分で切れる。**控えておいたリンクを後から開くことはできない。**
ブラウザのダウンロードは Authorization ヘッダーを付けられないため、認証は「押したとき」に
済ませ、受け取りの口には短命の券だけを渡している。長期のトークンを URL に載せると、
それ自体が鍵として履歴や画面共有に残ってしまう。

途中で切れた転送は、ブラウザが続きから取り直せる。ダウンロードはサーバーにも `data/` にも
触らないので、他の操作の実行中でも押せる。

**外から持ち込んだ zip を取り込める。** 別の機械で取ったバックアップや、配布されている
ワールドを、同じ画面から保管先に入れられる。取り込むだけで**ワールドには触らない**。
差し替えるかどうかは、このあと一覧から復元して、これまでどおりの関門（バージョンの確認と
ワールド名の入力）を通して決める。「置くこと」と「使うこと」を同時に決めさせないため。

受け付ける zip の形は 2 つ。どちらとも判断できないものは受け取らない。

| zip の中の形 | 扱い |
|---|---|
| `data/<名前>/level.dat` | そのまま保管する（管理コンソール自身が作る形） |
| `<名前>/level.dat` | `data/` 配下へ包み直してから保管する（配布ワールドに多い形） |

- `level.dat` が zip の直下にあるものは受け取らない。ワールド名が決まらないため。
  ワールド名のフォルダに入れてから固め直す
- ルート直下にワールドが複数あるものも受け取らない。どれを取り込むか勝手に選ばない
- 上限は**空き容量の半分**。包み直しのあいだ 2 つ分の場所が要るため

保管したファイル名の末尾には `imported` が付く。持ち込んだものだと後から分かる。
版はアーカイブ内の `level.dat` から読む。読めなければ `unknown` として取り込み、
復元のときに承諾を求める。

取り込みは `data/` を触らないので、操作の枠を消費しない。バックアップの取得や復元が
走っている最中でも送れる。

保持ポリシーは世代数と日数の**両方**を満たさないものだけを削除する。設定がどうであれ、
最も新しい 1 世代は必ず残る。

### `/settings` ゲーム設定

モード（ゲームモード）・難易度・MOTD・最大人数・描画距離・シミュレーション距離の
6 項目を、`.env` に書き込む。

ゲームモードは **接続してくる人に適用される**。既に接続している人のモードは
変わらない（`server.properties` の `gamemode` と同じ振る舞い）。

**ハードコアもモードの選択肢に並ぶが、ここからは選べない（灰色で表示する）。**
生成されたワールドの `level.dat` に焼かれる値なので、後から有効にしても
食い違うだけになる。それでも並べるのは、いまハードコアかどうかを知る手段が
これしか無いため。解除したい場合はハードコアでないワールドを新しく作る
（`MC_HARDCORE=FALSE` が書かれる）。

ハードコアのときは**難易度も灰色になる**。ハードに固定されているためで、
表示もハードのままになる。

**バージョン・サーバー種別・メモリ・ワールド名はここでは変えられない。** 前者は
ワールドの片道アップグレードを、メモリは Pi が固まる状態を、画面のひと押しで
起こせてしまうため。ワールド名は `/worlds` の切り替えで変える。

保存のしかたは 2 つ。

| ボタン | 何が起きるか | いつ使うか |
|---|---|---|
| 保存だけする | `.env` に書くだけ。サーバーには触らない | 人がいる時間帯に設定だけ入れておき、あとで再起動する |
| 保存して今すぐ反映 | `.env` に書いてから、保存 → 停止 → 起動で作り直す | すぐに効かせたいとき。接続中の人は切断される |

- 人が接続しているときに「今すぐ反映」を押すと、切断してよいか一度確かめる。
- サーバーが停止中は「今すぐ反映」を出さない。止まっているサーバーを勝手に起動しない。
- 書き込みは作り直しより**先に**行う。書き込みに失敗したら、まだ誰も切断していない段階で止まる。
- 画面を開いている間に `.env` を手で書き換えると、保存は競合として失敗する（上書きはしない）。
  読み込み直してから保存する。
- `.env` に読めない値（`MC_VIEW_DISTANCE=abc` など）があっても画面は開ける。
  既定値で補って表示し、何を補ったかを知らせる。

描画距離とシミュレーション距離は Pi の負荷を最も左右する。目安（描画距離 10、
シミュレーション距離 8、最大 10 人）を超えると注意を出すが、保存は止めない。
シミュレーション距離は描画距離以下でなければ保存できない。

MOTD には `§` の色コードを使えるが、`"`・`$`・`` ` ``・`\` と改行は使えない。
`.env` は docker compose がシェルに近い規則で読むため、展開や退避の解釈が揺れる文字を
値の段階で弾いている。

### `/system` リソース

ホスト（Pi 本体）の CPU・メモリ・ストレージの現在値。**コンテナではなく
ホストを見る。** ストレージはコンテナと共有で、空き容量はそのままサーバーの
生死に関わる。メモリも、MC 以外の使用分まで含めないと判断できない。

この画面だけは**開いている間 5 秒ごとに取り直す。** 他の画面が取り直さないのは
値が操作の前後でしか変わらないからで、ここは常に動いている値を見に来る場所
なので前提が違う。読むのは `/proc` と statfs だけでプロセスも生やさないため、
5 秒間隔でも負荷にはならない。画面を離れれば止まる。

**CPU 使用率は区間の平均で、瞬間値ではない。** `/proc/stat` が持つのは起動からの
累積値なので、2 点の差分でしか求められない。そのため画面を開いた直後の 1 回目は
「測定中」と出て、次の取得から値が出る。どの期間の平均かは画面にも添える。

| 項目 | 読む場所 | 補足 |
|---|---|---|
| CPU | `/proc/stat`、`/proc/loadavg` | 全コアをまとめた値。ロードアベレージはコア数と併記 |
| メモリ | `/proc/meminfo` | `MemFree` ではなく `MemAvailable`。回収できるキャッシュを空きに数える |
| ストレージ | `statfs` | `Bavail`。`df` の「使用可能」と同じで、root 用の予約分を除く |

帯の色は 90% から警告、95% から危険。80% を警告にしないのは、4GB の Pi では
MC だけで実 RSS 約 2.7GB を使い、メモリが常にそれなりに埋まっているため
（[raspberry-pi.md](raspberry-pi.md) のメモリ収支）。常時警告は警告として働かない。

**履歴は持たない。** 保持すれば置き場所と保持期間を決めることになり、4GB の Pi で
それを賄う理由が無い。推移を追いたくなった時点で、外の監視に任せるか改めて設計する。

読めない項目があっても画面は開く。項目ごとに理由を出して、残りは表示を続ける。
資源が苦しいときにこそ開く画面で、1 つ読めないだけで何も見えなくなるのが一番困る。
`/proc` は Linux にしか無いので、開発機（macOS）では CPU とメモリが
「この OS では取得できません」になり、ストレージだけが出る。

## 復元

取り消せない唯一の操作なので、関門を 2 つ置いてある。

1. **復元先のワールド名を打ち込む**（完全一致）
2. バージョンや名前が食い違うときは、**警告を読んだという承諾**

どちらの判定もサーバー側でもう一度やり直す。画面が「確認しました」と主張しても、
その画面が古い判定に基づいている可能性があるため信用しない。

### 復元先を選ぶ

アーカイブは `data/world/...` のように、取得したときのワールド名を持っている。
その後 `MC_LEVEL` を切り替えていると、素直に展開しても `data/world` が戻るだけで
**稼働中のワールドは何も変わらない**。これを避けるために復元先を選べる。

| 選択 | 何が起きる |
|---|---|
| アーカイブのワールド名（既定） | `data/<アーカイブの名前>/` に戻し、`MC_LEVEL` もそちらへ切り替える |
| 稼働中のワールド名 | 展開時にパスを書き換え、いま動いているワールドとして戻す |

### 手順

復元は「退避してから展開」であって上書きではない。

```
確認 → 空き容量 → 停止 → 退避 → 展開 → 設定 → 起動
```

現在のワールドは `data/<名前>.broken-<日時>` へ `mv` される。**取得後に増えた
ファイルは復元後のワールドから消えるが、退避先には残っている。**
展開に失敗したら自動で巻き戻す。起動に失敗した場合は巻き戻さず、退避を残したまま
失敗として報告する（手で直す余地を残すため）。

退避は自動で消さない。`/worlds` の「退避したワールド」に出るので、問題なく
動くことを確かめてから消す。

## 進行中の操作

操作は**同時に 1 つだけ**。実行中は全ての変更ボタンが押せなくなる。
画面上部の帯に手順（n/N）と進み具合とログが出る。

**画面を閉じても操作は止まらない。** 操作はサーバー側のもので、ブラウザは
見ているだけ。リロードすると帯が復帰し、押す前からのログも全部戻る。

別のタブや別の端末で始めた操作にも気づく。購読していない間だけ、進行中の操作を
定期的に探しているため。

## 手作業との対応

画面が何をしているかは [backup-restore.md](backup-restore.md) の手順と同じ。
片方しか使えない状況（SSH しか無い、コンソールが動かない）に備えて対応を残しておく。

| 画面の操作 | 相当する手作業 |
|---|---|
| 起動 / 停止 / 再起動 | `docker compose up -d` / `down` / `up -d`（`restart` ではない） |
| バックアップの取得（稼働したまま） | `save-off` → `save-all` → `zip` → `save-on` |
| バックアップの取得（停止して） | `down` → `zip` → `up -d` |
| 復元 | `down` → `mv data/<名前> data/<名前>.broken-<日時>` → `unzip -qo` → `up -d` |
| ワールドの切り替え | `.env` の `MC_LEVEL` を書き換えて `up -d` |
| ワールドの複製 | `save-off` → `save-all` → `cp -a` → `save-on` |
| バックアップの持ち出し（ダウンロード） | `scp pi@<Tailscale のホスト名>:~/minecraft-server/backups/backup-*.zip .` |
| zip の取り込み | `cp <zip> backups/`。ただし `<名前>/` 形式の zip は `data/` 配下へ包み直さないと復元できない |
| 退避の完全削除 | `rm -rf data/*.broken-* data/*.deleted-*` |

## 困ったとき

**起動直後に落ちる**
`journalctl -u mcadmind -e` を見る。`ADMIN_TOKEN` が未設定か短いのが最も多い。
`openssl rand -hex 32` の出力を `.env` に書く。

**画面が白い**
フロントエンドが埋め込まれていない。`./deploy/download.sh` で落とし直す。
Release のバイナリは埋め込みを CI で検証しているので、これで直らないなら
手元でビルドしたものが入っている（`make build` / `make build-arm64` で作り直す）。

**`docker` が見つからない**
systemd 配下では PATH が最小限になる。`.env` の `ADMIN_DOCKER_BIN` に
`/usr/bin/docker` のような絶対パスを書く。

**「他の操作が実行中です」から戻らない**
`data/.admin-console.lock` が残っている。mcadmind を再起動すると、中断として
検出してロックを外し、`save-on` を送り直す。それでも消えなければ手で削除する。

**画面の操作は成功したのに、ワールドが変わっていない**
`MC_LEVEL` が別のワールドを指している可能性がある。`/worlds` で「稼働中」の印が
どこに付いているかを確かめる。復元先の選択（上記）も同じ理由で存在する。

**`.env` を手で編集したら「外部から変更されました」と出た**
書き込む直前に、読んだときから変わっていないかを確かめている。画面を再読み込み
すれば直る。人の `vi .env` を潰さないための仕組み。
